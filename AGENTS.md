# AGENTS.md

## Role and scope

This repository is a React + TypeScript single-page application built with Create React App conventions. The app lives under `src/` and uses webpack-based build tooling configured in `config/` and `scripts/`.

This file defines repository-specific instructions for AI coding agents and contributors. Follow these rules in addition to any general project conventions.

## Required package manager

This repository must use Yarn for all dependency installation and script execution.

Use these commands instead of npm equivalents:

- Install dependencies: `yarn install`
- Start dev server: `yarn start`
- Run unit tests: `yarn test`
- Run tests in watch mode: `yarn test:watch`
- Run coverage: `yarn test:coverage`
- Lint: `yarn lint`
- Lint with autofix: `yarn lint:fix`
- Production build: `yarn build`

Important:

- Never use `npm install`, `npx`, `npm run`, or `npm test` in this repository.
- If Yarn is not installed, enable it with Corepack before running the repo commands: `corepack enable` and then `yarn install`.
- Keep commands consistent with the existing `package.json` scripts and use Yarn so lockfile and install behavior remain aligned.

## Environment and tooling

- Preferred Node version: current LTS-compatible version supported by the project dependencies.
- Use the repo-local scripts rather than ad hoc build commands when a repo script already exists.
- Respect CRA/Jest conventions and the configured test setup in `src/setupTests.ts` and `config/jest/*`.

## Repository structure

- `src/` — application source code
  - `src/components/` — UI components and tests
  - `src/services/` — API/service logic
  - `src/types/` — shared TypeScript types
  - `src/utils/` — test utilities and helper functions
- `public/` — static assets and HTML shell
- `config/` — webpack and Jest configuration
- `scripts/` — start/build/test scripts used by package.json
- `coverage/` — generated test coverage output; do not edit
- `build/` — generated production output; do not edit manually

## Development workflow

1. Before making changes, inspect the relevant component or service and nearby tests.
2. Prefer the smallest scoped change that solves the problem.
3. Keep TypeScript types explicit and consistent with existing patterns.
4. Preserve the current app architecture and naming conventions.
5. Update or add tests when behavior changes.

## Testing expectations

- Run the smallest relevant test command, not broad suite runs unless needed.
- For component changes, prefer targeted Jest runs if possible.
- Most commands should be executed through Yarn, for example:
  - `yarn test --watch=false` for a single run if needed
  - `yarn test --runInBand --watch=false` when a focused run is required
- Do not write tests that assert mock-only behavior; test the observable UI or function behavior instead.

## Code conventions

- Follow the existing TypeScript and React patterns already used in the repository.
- Keep components, hooks, and services focused and readable.
- Reuse existing shared utilities and types instead of creating duplicates.
- Avoid broad refactors unrelated to the requested task.
- Preserve accessibility and existing user-facing behavior while making the minimal fix.

## Build and verification

Before considering work complete, verify the affected behavior with the appropriate command using Yarn. Typical validation commands include:

- `yarn test`
- `yarn lint`
- `yarn build`

For a bug fix or feature change, prefer running the relevant test(s) first and then the smallest validation needed to confirm correctness.

## Files not to modify without a clear reason

- `coverage/`
- `build/`
- lockfiles generated by the package manager
- Generated configuration files unless the task explicitly requires it

## Instructions for agents

- Do not add unrelated dependencies.
- Do not switch the repo to npm or another package manager.
- Do not rewrite the app to a different framework or architecture without explicit approval.
- Do not remove existing tests or skip validation when behavior changes.
- Keep commit scope narrow and aligned with the issue or request.
